**Scenario Ref ID Generation** (lines ~400-420):

```python
def save_scenarios(self, scenarios: list[Scenario]) -> None:
    # Get existing scenarios for this requirement
    existing = self.get_scenarios(requirement_id)
    existing_count = len([s for s in existing if s.id not in [sc.id for sc in scenarios]])
    
    # Auto-generate scenario_ref_id if not present
    for idx, scenario in enumerate(scenarios):
        if not scenario.scenario_ref_id:
            scenario.scenario_ref_id = f"US{existing_count + idx + 1:02d}"
```

**Test Case Ref ID Generation** (lines ~500-530):
```python
def save_test_cases(self, test_cases: list[TestCase]) -> None:
    # Get parent scenario
    scenario = self.get_scenario(test_case.scenario_id)
    
    # Get existing test cases for this scenario
    existing_tcs = self.get_test_cases(test_case.scenario_id)
    existing_count = len([tc for tc in existing_tcs if tc.id != test_case.id])
    
    # Auto-generate test_case_ref_id if not present
    if not test_case.test_case_ref_id and scenario.scenario_ref_id:
        test_case.test_case_ref_id = f"{scenario.scenario_ref_id}-TC{existing_count + 1:02d}"
```

## Understanding the "FR-01" Issue

**User Observation**: "I see FR-01 instead of US01"

**Explanation**:
- **FR-01** is the **Requirement ID** (Feature Requirement) from the uploaded Excel/JIRA data
- **US01** is the **Scenario ID** (User Story) auto-generated by our system
- Both are displayed, but in different columns:
  - Scenarios table shows **FR-01** in the "Requirement" column (parent requirement)
  - Scenarios table shows **US01** badge next to the scenario name (scenario ref ID)

This is **working as designed**. The hierarchy is:
```
Requirement (FR-01) → Upload/Import data
  └─ Scenario (US01) → Auto-generated by system
       └─ Test Case (US01-TC01) → Auto-generated by system
```

## Data Migration for Existing Records

**Note**: Existing scenarios and test cases created before this implementation will NOT have ref IDs automatically populated. They remain NULL in the database until:

1. **Option A**: Re-generate scenarios/test cases (will get new IDs)
2. **Option B**: Run a migration script to populate ref_ids for existing records
3. **Option C**: Manually update records via SQL

### Migration Script (if needed)

```python
# Script to populate ref_ids for existing scenarios and test cases

from backend.database.db import SessionLocal
from backend.database.db_models import ScenarioDB, TestCaseDB, RequirementDB
from sqlalchemy import select

session = SessionLocal()

# Update scenarios
requirements = session.execute(select(RequirementDB)).scalars().all()
for req in requirements:
    scenarios = session.execute(
        select(ScenarioDB)
        .where(ScenarioDB.requirement_id == req.id)
        .order_by(ScenarioDB.created_at)
    ).scalars().all()
    
    for idx, scenario in enumerate(scenarios):
        if not scenario.scenario_ref_id:
            scenario.scenario_ref_id = f"US{idx + 1:02d}"

# Update test cases
scenarios = session.execute(select(ScenarioDB)).scalars().all()
for scenario in scenarios:
    if scenario.scenario_ref_id:
        test_cases = session.execute(
            select(TestCaseDB)
            .where(TestCaseDB.scenario_id == scenario.id)
            .order_by(TestCaseDB.created_at)
        ).scalars().all()
        
        for idx, tc in enumerate(test_cases):
            if not tc.test_case_ref_id:
                tc.test_case_ref_id = f"{scenario.scenario_ref_id}-TC{idx + 1:02d}"

session.commit()
print("Migration complete!")
```
