## Summary
The change replaces LiteLLM's broken global `langsmith` callback with a per-role `_LLMTrace` (spec 0003 AC-11) that sends one LangSmith "llm" RunTree per role completion, tagged with `llm_role`/`llm_model`, wired into every role-based completion and streaming path. `_init_langsmith_tracing()` is removed; tracing is exception-safe (start/end catch everything and never block or delay the call, and `end()` is idempotent). An AC-11 regression test covers the success path. The change is sound; the only real gap is that trace error paths and the streaming trace instrumentation are not exercised by any test.

## Minor
### 🟡 Trace error paths and streaming trace wiring are untested, `backend/services/llm.py`
`trace.end(error=exc)` on `RateLimitError` (line 543) and generic `Exception` (line 552) in `_complete`, the equivalents in `stream_chat` (lines 642, 653), and the stream `done()` trace end (line 673) — including the new `trace` parameter on `_stream_usage_recorder` — are not exercised by any test. Only the success path is covered (the new regression test). With TEST_SIGNAL=configured, new/error-handling instrumentation lacking coverage is at least a Minor. Risk is low because tracing is exception-safe and never breaks the call, but a silent failure to end/send a run on errors would go undetected.
**Suggested fix**: add tests that drive a role `generate`/`stream_chat` through a 429, a generic error, and a streamed call, asserting the run is ended with `error` set and `end_time` present (streaming included).

## Nits
### ⚪ `backend/services/llm.py:368`
`end()` reduces the error to `str(error)`, discarding the exception type. When a trace fails to send, the warning only has the message, which limits debuggability. Preserve the exception type (or log it) alongside the message.

## Strengths
- Exception-safe tracing: `_LLMTrace.start()` and `end()` catch all exceptions and never block or delay the LLM call; `end()` nils `self._run` before posting, so double-posting / double-ending cannot occur even if called twice.
- The AC-11 regression test (`test_role_call_sends_a_langsmith_run_with_role_and_model`) is a strong, targeted regression test asserting one run, `run_type == "llm"`, `end_time` set, correct metadata/tags, and that no global `langsmith` callback remains.

## Test coverage
Covered: role config parsing, which caller uses which role (AC-1/AC-2/AC-12), pool rotation/cap/pacing/429/max-wait (AC-3 to AC-8), settings API (AC-10), hidden retries `num_retries=0` (AC-13), and the LangSmith success-path trace (AC-11).
Not covered: trace error paths (RateLimitError/Exception in `_complete` and `stream_chat`) and the entire streaming trace wiring (`_stream_usage_recorder(trace=...)`). Core pool/429/pacing behavior remains well covered.
